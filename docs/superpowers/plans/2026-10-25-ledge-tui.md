# `ledge tui` Implementation Plan

**Goal:** a terminal interface for Ledge, started by `ledge tui`, that does what the island and Desktop do from any terminal where the daemon runs (Linux, macOS, a server over SSH, a tmux pane): the « À toi » list, projects by branch, the terminal preview, a session's thread with its diffs, Ask Ledge with its cards, and the launch form.

**Mockup:** https://claude.ai/artifact/6pq9nMXiLwcsACTiCsfeag (four screens: Vue d'ensemble, Session, Demander à Ledge, Nouvelle session).

**Architecture:** a new command in `packages/ledge` (`src/tui/`), written with Ink 7 (React 19, already the workspace's React). It is a fleet client like Desktop: `@ledge/fleet`'s `createFleetClient` over the `ws` package, the daemon token read from `~/.ledge`, remote machines reached through the local daemon's `/ssh/<alias>` as today. State comes from `@ledge/fleet`'s store (`useDaemon`, `useMachines`, built on `useSyncExternalStore`, which Ink supports). Rendering is split into **pure view models** (tested with vitest, no Ink) and thin Ink components. **No daemon change, no protocol change.**

**Tech Stack:** TypeScript (ESM), Ink 7.1.1, React 19, `ws`, vitest, `ink-testing-library`, tsup.

## Global Constraints

- Node ≥ 22 (the CLI's `engines`); the TUI runs where `ledge` runs.
- The hook path must stay as fast as today: `ledge tui` is a dynamic `import('./tui/index.js')` in `cli/index.ts`, and tsup must keep Ink and React out of the chunk the hook loads (check `dist/cli` after build).
- `react` and `ink` become `dependencies` of `@paradow/ledge`; `@ledge/fleet` and the pure parts of `@ledge/ui` are bundled (`noExternal`), like `@ledge/protocol` today. Only React-DOM-free modules of `@ledge/ui` may be imported (`reply/parse`, `thread/turns`, `thread/tools`, `chat/format`, `bots/poseFor`).
- No `localStorage` in Node: every `localStorage` use in `@ledge/fleet` is already inside `try`, except `configure()` for a non-daemon machine list, which the TUI never calls (it uses `machinesFromDaemon: true`).
- Every user-facing string lives in `tui/i18n/{fr,en}.ts` (French is the source of truth, `en` typed against it); no string literal in a component.
- Tests: `pnpm vitest run <file>` from `packages/ledge`; full gate `pnpm -r typecheck && pnpm test` from the root.
- Work only in the worktree `../ledge-tui`, branch `feat/ledge-tui`.

## Decisions made while planning

- **Ink, not blessed / a hand-made renderer:** the mockup asks for it, it reuses React and `@ledge/fleet`'s hooks as they are, and `ink-testing-library` gives frame tests.
- **Fleet client, not `src/client.ts`:** `client.ts` is a one-shot request client (queue + `next`). The TUI needs reconnection with backoff, several machines, chat turns and launches routed per machine: all already in `createFleetClient`. Options: `{ prefix: 'tui', keepStale: true, machinesFromDaemon: true, token }`, `WebSocketImpl: ws` (it has `onopen`/`onmessage` and takes subprotocols, so the `ledge.<token>` subprotocol works unchanged).
- **Decisions are shared, not copied:** `apps/desktop/src/fleet/decisions.ts` (`useDecisions`: one send per session, `expect` with `pendingKey`, settled when the request changes, refused or 8 s timeout) moves to `@ledge/fleet/decisions` with its copy and notify passed in; Desktop imports it from there. The TUI uses the same hook. This is the only change outside `packages/ledge`.
- **Copy and language (user's choice):** French and English from the first PR. `tui/i18n/fr.ts` (source of truth) and `en.ts` (`typeof fr`), a small `useT()` context. Wording follows Desktop's `fr.ts` / `en.ts` (« Votre accord » / « Needs you », etc.) but is not imported from the app (a CLI cannot depend on `apps/desktop`).
- **Settings (user's choice):** a Settings screen (`5`, or `,`), with one setting at first: the language (Français / English). Stored in `~/.ledge/tui.json` (`ledgeDir()`, so `LEDGE_HOME` is honoured), parsed with zod, unknown keys kept; a missing or broken file falls back to the default. The default comes from `LC_ALL` / `LC_MESSAGES` / `LANG` (`fr*` → French, anything else → English). Not shared with Desktop: `IslandPrefs` has no language and the daemon must not change. The screen is a list of settings so `--notify` can later become one too.
- **One PR (user's choice):** Tasks 0 to 12 land together on `feat/ledge-tui`.
- **`useDecisions` moves to `@ledge/fleet` (user's choice).**
- **Embedded terminal → `a`:** the Ink app is unmounted (`instance.unmount()` after leaving raw mode and the alternate screen), the command from `fleet.terminal(id)` runs with `stdio: 'inherit'` and `attachEnv` (TMUX removed, so it works from inside tmux), then the app is rendered again on the same state. For a remote machine `terminal()` already gives `ssh -t … ledge attach <id>`. An OMP session has no pane: `a` says so (same text as `ledge attach`).
- **Notifications:** on a session becoming pending (`changeOf` from `@ledge/fleet/changes`), write BEL, or OSC 9 (`ESC ] 9 ; <text> BEL`) with `--notify=osc9`; `--notify=off` mutes. Inside tmux, OSC 9 is wrapped in the DCS passthrough. Default `bell`.
- **Screen:** alternate screen buffer on start, restored on exit and on `SIGINT`/`SIGTERM`/uncaught error. Under 100 columns the overview drops the right column: `↵` opens the session screen instead.
- **Glyphs:** the mockup's `◆ ● ○ ? ⎇ ↳ ✉`; `LEDGE_TUI_ASCII=1` (or a non-UTF-8 locale) switches to ASCII, since `⎇` is ambiguous-width in some terminals.

## What the build changed from this plan

- **Ink 7.1.1, not 6.** It has `alternateScreen` and `suspendTerminal` built in: the alternate screen, its restore on exit and on a signal, and the hand-over to `ledge attach` need no code of ours (`screen.ts` was not written).
- **`packages/ledge/tsconfig.json`** moves to `moduleResolution: Bundler` with the DOM lib: `@ledge/fleet` imports without extensions and names `WebSocket` and `localStorage`. Every existing file type-checks unchanged.
- **More shared with Desktop than planned:** besides `useDecisions`, Desktop's launch form model (`launch/model.ts`) and `useModels` moved to `@ledge/fleet` (`launch.ts`, `models.ts`), Desktop re-exporting them. Desktop's own tests pass unchanged.
- **The launch form has a typed folder** (« Dossier », `~` allowed) next to the project's repositories (or the machine's recent folders when there is no project), instead of a folder browser.
- **« Échanges »** reads each session's `lastMessage`, not the threads: no thread has to be loaded for it.
- **Launch is `ctrl+s`** (and `↵` on the last field): terminals do not tell ctrl+↵ from ↵.
- **Task 0 outcome:** the fleet client works in Node over `ws` with the token as subprotocol; `ledge hook`'s chunks import neither `ink` nor `react` (only `dist/cli/tui-*.js` does).

## Review Focus

1. **Hook latency:** `ledge hook` must not load Ink/React → Task 1 check on the built output.
6. **Language switch** re-renders every screen at once, persists, and a broken `tui.json` never stops the TUI → Task 11.
2. **A decision on a request that just changed** is refused by the daemon (`expect.key`), never applied to the next one → shared `useDecisions` tests (Task 4).
3. **Terminal restored** after `a`, `q`, ctrl+c, a crash, and a daemon that goes away mid-session → Task 7 tests.
4. **Remote machine down:** its sessions stay listed, flagged offline (`keepStale`), and actions on them say so instead of sending → Task 3, Task 4.
5. **Nothing launches without a keypress:** an Ask Ledge card only launches on `↵` on that card → Task 9.
