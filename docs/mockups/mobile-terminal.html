Le terminal d'un agent sur le téléphone

Maquette de référence pour la spec docs/superpowers/specs/2026-11-02-mobile-terminal-design.md. Écrans de l'app mobile (apps/mobile), largeur 360 px, gouttière 16 px, tokens de @ledge/ui. Les encadrés jaunes sont des notes, absentes de l'app. Le contenu du terminal est un exemple.

En bref : l'écran Terminal devient un vrai terminal, en direct et en couleurs, à la taille du PC (le téléphone ne redimensionne jamais l'agent). On le lit sans rien confirmer. Prendre la main demande la passkey, puis ouvre le clavier avec une rangée de touches spéciales ; la main se rend seule après 5 min sans frappe, 30 min au plus, ou dès que l'appli passe en arrière-plan. Le PC voit « Téléphone au clavier » et peut reprendre la main.

Ouvert depuis le fil (bouton Terminal de l'en-tête, inchangé). Aucune confirmation : le téléphone voit déjà l'aperçu aujourd'hui. Le pane du PC fait ici 200 × 52.

10« Reprendre la main » envoie terminal.release { id } (message local nouveau) : le téléphone reçoit term.released { why: 'pc' }. Taper au clavier du PC ne retire pas la main : les deux claviers peuvent taper, comme deux fenêtres tmux. Pas de confirmation.

    

    

      
5b · Réglages, Accès mobile

      

        
Taper dans les terminaux depuis le téléphone
Un appareil lié peut prendre la main sur le terminal d'un agent, après la vérification de sa passkey. Sans ce réglage, le téléphone lit le terminal sans pouvoir y taper.

      

      
11Désactivé par défaut. Le couper retire la main à tout téléphone qui la tient (why: 'pc'). Stocké avec les autres réglages mobiles du daemon.

    

  


  
  
6. Spécification pour le dev

  

    
Protocole (phone.ts)

    

      
SensMessage

      
téléphone → PCterm.open { op, id }, term.hold { op, tid, assertion }, term.input { tid, n, data ≤ 4096 }, term.release { tid }, term.resync { tid }, term.close { tid }

      
PC → téléphoneterm.opened { op, tid, cols, rows, screen ≤ 64 Kio, cursor, seq }, term.output { tid, seq, data }, term.size, term.held { tid, until }, term.released { tid, why }, term.exit { tid, why }

      
snapshotdaemon.terminal, daemon.terminalInput ; ConfirmPurpose gagne terminal.

Accessibilité

    
    
      
  • Le terminal : aria-label « Terminal de Nova », mode lecteur d'écran de xterm activé ; l'état (lecture seule / au clavier) en role="status".
    • 
      
  • La main tenue se voit par le cadre et par le texte « Vous tapez dans Nova » : jamais par la seule couleur.
    • 
      
  • Touches : boutons avec nom (« Contrôle, armé », « Flèche haut ») ; aria-pressed pour Ctrl, Alt et Ligne.
    • 
    

    
Critères d'acceptation

    
    
      
  1. Ouvrir le terminal d'une session : l'écran de l'agent s'affiche en couleurs en moins d'une seconde, puis suit en direct ; le Claude Code du PC garde sa largeur.
    2. 
      
  2. Prendre la main → Face ID → taper /help ↵ : l'aide s'affiche sur le PC et sur le téléphone.
    3. 
      
  3. Passer l'appli en arrière-plan : la main est rendue ; revenir : lecture seule, « Reprendre la main » redemande Face ID.
    4. 
      
  4. Réglage du PC coupé : aucun bouton pour taper, et un term.input forgé est refusé.
    5. 
      
  5. Une sortie massive (yes pendant 30 s) : le lien ne tombe pas, les décisions arrivent toujours, l'écran se rattrape par sauts.
    6.
